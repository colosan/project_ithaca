# ADR-0006 · 디자인 먼저 확정하고 구현한다

- 상태: 확정 (2026-10-01)

## 맥락

이 제품은 디자인이 결과를 좌우한다. 실행 환경은 iPhone, iPad, Mac, Android, Windows로 다섯 가지이고, 창 크기에 따라 레이아웃이 바뀌어야 한다.

디자인 시스템 운영에서 흔히 검증된 원칙을 그대로 가져온다.
- 값의 정본은 JSON 축이다.
- 생성물은 손으로 고치지 않는다.
- 등록된 이름만 쓴다.
- 검사에 BLOCK이 하나라도 있으면 완료로 치지 않는다.

반대로 협업, 배포, Electron 셸, agent 실행, Figma 연동은 빼고 **가볍게 검수만 하는 시스템**으로 만든다.

## 결정

1. **순서**: PRODUCT.md → DESIGN.md → 토큰 6축 → 화면 목록 → 프로토타입 → 검수 → 버전 동결 → 네이티브 구현.
2. **토큰 6축**: color, typography, spacing, sizing, effects, layout. layout 축에는 size class, pane 폭, 에디터 줄 길이 상한(measure)이 들어간다.
3. **기기가 아니라 size class를 기준으로 설계한다.** Mac이나 Windows 창도 폰만큼 좁아질 수 있기 때문이다.

| class | 폭 | 레이아웃 |
|---|---|---|
| compact | < 600 | 한 번에 1단, push navigation |
| medium | 600–839 | 2단 (목록 + 에디터). 라이브러리는 overlay로 연다 |
| expanded | 840–1199 | 3단 (라이브러리 / 목록 / 에디터) |
| large | ≥ 1200 | 3단 + 설정 참조 패널 |

4. **화면 하나는 폴더 하나다**: `design/screens/<slug>/{spec.md, prototype.tsx, meta.json}`.
5. **workbench는 혼자 쓰는 검수 도구다.** 승인이나 검토 요청 같은 협업 워크플로는 두지 않는다. 피드백은 대화로 바로 전달한다.
   - **캔버스 (홈).** Figma처럼 넓은 공간에 화면 카드를 live preview로 띄운다. 카드는 `meta.json links`에 적힌 이동 경로를 따라 화살표로 연결된다. 카드를 끌면 그 위치가 `design/canvas.json`에 저장된다. 카드를 클릭하면 상세 화면으로 들어간다.
   - **상세 화면.** 프레임마다 실제 기기나 창 프리셋(`design/viewports.json`)을 고를 수 있고, 오른쪽·아래·모서리를 끌어서 크기를 바꿀 수 있다.
     - Windows는 해상도를 디스플레이 배율로 나눈 값을 논리 크기로 쓴다. 예를 들어 1920×1080이 150% 배율이면 1280×720이다. 같은 모니터라도 배율에 따라 size class가 달라진다.
     - 테마는 light / dark / 둘 다 중에서, UI 언어는 ko / en 중 하나를 고른다.
   - **샘플 원고.** 한국어와 영어를 섞은 원고 하나(`fixtures/sample-project.json`)를 쓴다. 두 문자 체계의 조판을 한 화면에서 함께 본다.
6. **프로토타입에서 하는 것과 하지 않는 것.**
   - 레이아웃, 토큰, 상태, 문구를 확정한다.
   - 네이티브 컨트롤(내비게이션 바, 시트, 메뉴)은 spec에 "플랫폼 관례를 따른다"고만 적는다. 웹에서 흉내 내지 않는다.
7. **네이티브 구현을 검증하는 방법.** SwiftUI와 Compose의 preview 스크린샷을 프로토타입 스크린샷과 비교한다. 이때 둘 다 같은 `fixtures/` 원고를 쓴다.
