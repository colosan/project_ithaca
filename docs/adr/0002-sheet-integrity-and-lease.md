# ADR-0002 · sheet 무결성과 점유(lease)

- 상태: 확정 (2026-10-01)

## 맥락

이 앱은 소설을 쓰는 앱이다. 그래서 글자 단위 CRDT로 자동 merge하면 위험하다. 예를 들어 두 기기에서 같은 문장을 각각 고치면, 합쳐진 결과가 문법적으로는 성공했는데 의미가 망가진 문장이 될 수 있다.

## 결정

1. **동시 수정을 막고 sheet 단위로 점유한다.**
   - 다른 기기가 점유 중인 sheet를 열면 이런 메시지가 뜬다: "{기기}에서 편집 중 · 마지막 활동 N분 전 · [읽기 전용] [점유하기]".
   - 점유를 뺏긴 기기는 즉시 읽기 전용으로 바뀐다.
2. **목차도 sheet처럼 다룬다.** 목차에는 sheet 목록, 연재 순서, 생성·삭제가 들어 있다. 목차를 편집하는 동안에도 점유 규칙을 그대로 적용한다.
3. **sheet 본문은 선형 hash chain으로 저장한다.**
   - 블록 구조: `Block { hash, parent_hash(es), sheet_id, epoch, device_id, actor(me|claude), kind(Edit|Lease|Merge), body, created_at }`
   - 동시 수정이 없으므로 sheet 본문에는 CRDT가 필요 없다.
4. **오프라인 분기는 자동으로, 결정적으로 판정한다.**
   - 같은 parent에서 블록이 갈라지면 epoch이 높은 쪽을 본문으로 삼는다.
   - epoch이 같으면 device_id 순으로 정한다.
   - 진 쪽은 **분기 사본**으로 보존한다. 데이터 손실은 없다.
5. **분기 사본은 다음에 그 sheet를 열 때 해소한다.**
   - 좌(본문)와 우(사본)를 나란히 보면서 **양쪽을 모두 편집**할 수 있다. 문단마다 [→]/[←]로 내용을 가져온다.
   - diff는 문단 단위로 계산하고, 바뀐 문단 안에서는 글자 단위로 강조한다.
   - 해소하면 `Merge { parents: [본문, 사본] }` 블록을 기록한다.
   - 해소하기 전까지 그 sheet는 읽기 전용이다.
   - 폰처럼 화면이 좁을 때는 좌우 분할 대신 문단 카드를 swipe하는 방식으로 보여준다.
6. **Claude(MCP)의 쓰기도 같은 규칙을 따른다.** actor가 `claude`인 블록으로 기록되므로, Claude가 한 변경만 골라서 볼 수 있고 되돌릴 수 있다.

## 결과

- 의존성으로는 diff용 `similar`(Apache-2.0)만 쓴다. Automerge는 쓰지 않는다.
- 블록 파일은 hash로 이름을 붙인 불변 파일(`changes/<hash>`)이다. 그래서 아무 폴더나 저장소로 동기화해도 파일 단위 충돌이 생기지 않는다(→ 0003).
