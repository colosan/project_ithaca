# ADR-0005 · 다국어 (ko / en 기본)

- 상태: 확정 (2026-10-01)

## 결정

1. **정본은 `design/strings/{ko,en}.json` 하나로 둔다.**
   - 키는 평평한 점 표기로 쓴다: `section.lore`.
   - 값은 문자열이다. 복수형이 필요한 경우에만 `{ "one": …, "other": … }` 객체로 쓴다.
   - 자리표시자는 `{name}` 형식이다.
2. `tools/design-gen`이 이 정본에서 **typed accessor**를 생성한다: Swift `L10n`, Kotlin `L10n`, TS `strings.ts`. 그래서 오타 난 키는 컴파일 에러가 된다.
3. **앱 안에서 바로 언어를 바꿀 수 있게 한다.** 선택지는 시스템 / 한국어 / English이고, 재시작하지 않는다. 이를 위해 OS 리소스(.xcstrings, strings.xml) 대신 생성한 테이블을 직접 읽는다.
   - 기여자는 `ja.json` 하나만 PR로 올리면 언어를 추가할 수 있다.
4. **복수형 규칙**: 지금은 ko와 en만 지원한다. ko는 복수형을 구분하지 않고, en은 1이면 `one`, 그 외에는 `other`를 쓴다. 규칙이 다른 언어를 추가할 때 이 부분을 확장한다.
5. **UI 언어와 원고 언어는 분리한다.**
   - 분량 단위는 작품의 원고 언어를 따른다. ko 원고는 공백 포함 글자수, en 원고는 단어 수로 센다.
   - Rust core는 문구를 들고 있지 않고 에러 코드(enum)만 반환한다.
   - MCP tool 설명은 영어로 고정한다.
6. **용어 충돌을 주의한다.** 한국어 "설정"은 작품의 설정집(Lore)을 뜻한다. 앱 환경 설정은 "환경설정"(Settings)이라고 쓴다.

## 검증 (`design:check`)

다음 경우는 BLOCK으로 처리한다.
- 어떤 키가 모든 locale에 있지 않은 경우
- locale끼리 자리표시자 이름이 다른 경우
- 값이 비어 있는 경우
- 프로토타입 JSX 안에 문구를 하드코딩한 경우
