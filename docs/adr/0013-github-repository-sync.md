# ADR-0013 · GitHub 비공개 저장소로 동기화

- 상태: 채택 (2026-11-05, 0.11.0)
- 관련: ADR-0002(블록 · 갈라짐), ADR-0003(transport — 이 결정이 첫 transport), core/API.md §Sync

## 맥락
소유자: "휴대폰이나 타 PC랑도 공유해보고 싶은데 … 아이클라우드는 못써 … github로도 가능하게 뚫어줘 프라이빗레포에 올려주고 클라우드 저장소로 쓰게".
ADR-0003 의 1순위 relay 서버는 서버를 운영해야 하고, iCloud 는 쓸 수 없다. GitHub 비공개 저장소는 소유자가 이미 쓰고 있고, 기기가 동시에 켜져 있지 않아도 된다(store-and-forward).

## 결정
1. **공유 저장소 = 소유자의 GitHub 비공개 저장소 하나.** 저장소에는 블록 파일만 `projects/<project>/<chain>/<hash>` 로 둔다(+ 첫 커밋의 README). 블록은 바뀌지 않고 이름이 hash 라 파일 단위 충돌이 없다(ADR-0002).
2. **core 는 무엇을, 앱은 어떻게.** core: `sync_files` · `sync_plan(remote, base)` · `sync_read` · `sync_ingest`(검사 · 쓰기 · 다시 읽기). 앱(Swift, URLSession): 목록 · 받기 · 올리기. iOS 앱도 같은 Swift 코드를 쓴다.
3. **지워진 것은 되살리지 않는다.** `base` = 지난 동기화 때 저장소 목록(앱이 그 커밋 id 를 기억). base 에 있었는데 한쪽에 없으면 그쪽에서 영구 삭제한 것 → 다른 쪽에서도 지운다. 묘비(tombstone)가 있는 시트의 파일도 저장소에서 지운다.
4. **목차 갈라짐은 바로 합친다.** 두 기기가 따로 시트를 만들면 목차가 갈라진다 → `Toc::merge_from`(상대에만 있는 시트 · 묘비를 더하고 나머지는 이긴 쪽) 결과로 merge 블록. 블록은 기기와 상관없이 같은 바이트(device `"sync"`, 늦은 부모의 시각 · epoch)라 두 기기가 동시에 합쳐도 다시 갈라지지 않는다. **원고 본문 갈라짐은 ADR-0002 대로** 이긴 쪽을 보이고 진 쪽은 갈라진 사본(변경 기록에 있음)으로 남긴다 — 글을 자동으로 합치지 않는다.
5. **GitHub API**: 목록은 REST trees(304 는 한도에 안 셈 — 15초마다 ETag 로 확인), 받기는 GraphQL 100개씩, 올리기는 GraphQL `createCommitOnBranch`(한 번에 300개, `expectedHeadOid` 로 다른 기기와 겹치면 다시 목록부터). 저장한 뒤 모아서 올린다(4초 뒤, 지난 실행에서 30초가 지나지 않았으면 30초까지 — GitHub 은 시간당 커밋 수를 제한한다).
6. **토큰**: 소유자가 만든 Fine-grained 토큰(그 저장소 하나 · Contents 읽기 쓰기). 라이브러리 폴더 옆 `github-token` 파일(0600)에 둔다 — 키체인은 ad-hoc 서명 앱이 업데이트될 때마다 암호를 다시 묻는다. 공개 저장소는 연결을 거절한다.
7. **암호화하지 않는다(지금은).** 비공개 저장소라도 GitHub 는 내용을 읽을 수 있다 — 환경설정에 그대로 적는다. 종단 간 암호화는 기기 묶기(pair-device)와 함께 나중에.

## 결과
- 동기화 탭이 생겼다(GitHub 저장소 · 토큰 · 지금 동기화 · 연결 끊기). 하단 저장 표시는 연결되면 구름(맞춰짐 · 동기화 중 · 안 됨).
- 같은 원고를 두 기기에서 거의 동시에 고치면 갈라진다. 갈라진 사본 정리 화면(branch-resolve)은 아직 없다 — 진 쪽 글은 변경 기록에서 되살린다.
- 점유(lease, ADR-0002 §1)는 아직 없다.
- 저장소 목록 한 번에 10만 파일까지는 한 요청, 넘으면 폴더별로 나눠 읽는다.
- relay · P2P(ADR-0003)는 그대로 계획으로 남는다.
