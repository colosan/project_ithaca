# 2026-10-24 새벽 자율 개발 세션 (03:10–07:10) — 돌아와서 볼 것

## 결과 한 줄

원래 계획(Rust core + SwiftUI)대로 **Mac 앱**을 만들었다. **0.2.0 → 0.5.0**을 GitHub Releases로 배포했고, `/Applications/Ithaca.app`에 0.5.0이 설치돼 있다. 앞으로의 업데이트는 앱이 하루 한 번 확인한다(Sparkle).

## 바로 해 볼 것

1. `/Applications/Ithaca.app`을 연다.
2. 웹 버전에 쓴 원고가 있으면 가져온다.
   1. 웹 버전에서 환경설정 → 백업 → 지금 백업을 누른다.
   2. Mac 앱에서 파일 → **웹 버전에서 가져오기…**를 고른다.
   - 텍스트 파일 폴더(한글 · 메모장 내보내기 등)는 **텍스트 폴더 가져오기…**로 가져온다.
3. **한글로 직접 타이핑해 본다.** 세션 동안 화면이 잠겨 있어서 실제 키보드 입력은 확인하지 못했다. 오프스크린 자체 시험은 통과했다(조합 중 저장 · 칠하기, 단어 단위 되돌리기).
   - 문장 중간 삽입, 조합 중 Backspace · Enter · 스페이스, ⌘Z가 음절이 아니라 단어 단위로 되는지 확인한다.
   - 이상하면 바로 알려 준다. 가장 중요한 P0다.
4. 환경설정 → Claude를 켜고 작품을 체크한 뒤 **설정 파일에 추가**를 누르고 Claude Desktop을 재시작한다. 그러면 Claude가 원고와 설정집을 읽을 수 있다(읽기 전용).

## 주인이 한 번 해야 하는 일

- **고정 서명 인증서 만들기.** 터미널에서 `tools/mac/make-signing-identity.sh`를 실행한다. 로그인 키체인 암호를 묻는다.
  - 지금은 ad-hoc 서명이라 업데이트할 때마다 macOS가 다른 앱으로 볼 수 있다(권한 프롬프트가 다시 뜰 수 있다).
- **업데이트 서명 키 백업.** `~/Library/Application Support/Ithaca-Release/sparkle_ed25519_private.key`(키체인 항목 `ithaca`와 같은 키)를 암호 관리자 등 안전한 곳에 복사해 둔다. **잃어버리면 이미 설치된 앱이 업데이트를 못 받는다.**
- **클릭으로 하는 업데이트 1회 확인.** 화면이 잠겨 있어서 "설치 후 다시 시작" 버튼을 직접 눌러 보지 못했다. 자동 설치 경로(0.9.0 → 0.9.1 시험판)는 끝까지 검증했다.
  - 다음 릴리스가 나오면 메뉴 → 업데이트 확인…으로 한 번 해 본다.

## 결정 — 검토 필요

모두 `design/PRODUCT.md`의 "검토 필요" 표와 ADR에 적어 두었다. 바꾸려면 그 표를 고치고 말해 주면 된다.

- ADR-0008: Mac 동결 해제, Xcode 없이 SwiftPM 빌드, Sparkle과 GitHub Releases, 데이터 형식 버전과 마이그레이션(변환 전 전체 백업)
- ADR-0009: Claude 연결은 stdio MCP, 읽기 전용, 토큰 없음, 보여줄 작품을 직접 체크
- 글자수 기준: **올릴 글 기준**(제목 줄 · Markdown 기호 제외)을 기본으로 보이고, 원고 전체 글자수는 정보 탭에 둔다
- 회차
  - 연재 폴더의 새 시트는 자동으로 다음 번호를 받는다
  - 프롤로그 · 외전 · 공지는 번호에서 뺀다
  - 웹 · 텍스트 가져오기는 첫 폴더에 초고 상태로 번호를 매긴다
- 백업: 하루 한 번, 최근 7일 + 4주를 보관한다. 빈 라이브러리는 백업하지 않는다. 폴더 이름은 현지 시각이다
- 라이브러리 잠금: 앱을 두 개 열면 두 번째는 읽기 전용으로 열린다
- 손상된 시트
  - 마지막으로 온전한 내용을 보이고 저장을 거부한다
  - "백업에서 되살리기"와 "마지막 온전한 내용으로 계속 쓰기"를 둔다
  - 깨진 파일은 지우지 않고 `damaged/`로 옮긴다
- 맞춤법 검사: 한국어 원고는 기본으로 꺼 둔다. 외부 맞춤법 검사기는 쓰지 않는다(서버 없음 원칙)
- 서체: Pretendard를 앱에 넣었다. 본문 서체 선택은 다음에 만든다

## 무엇이 들어갔나 (버전별)

- **0.2.0**

  - SwiftUI 앱: 3단 화면, TextKit 2 에디터, 메뉴 · 단축키, 팔레트, 변경 기록, 내보내기, 휴지통과 되돌리기, 설정
  - 데이터 안전: 라이브러리 잠금, 캐시 검증, 저장 실패 시 시트 전환 · 종료 거부, 손상 복구
- **0.3.0**: Claude 연결(ithaca-mcp), 예약 · 다음 연재일, 폴더 통계, 플랫폼 기준 목표, 외전 제외
- **0.4.0**: Word(.docx) 내보내기, MCP 견고성(잘못된 입력 · 긴 출력 나눠 보내기), 텍스트 가져오기 규칙(프롤로그 맨 앞), 읽기 전용 화면 정리

## 검증한 방법

- 매 라운드마다 하위 에이전트가 앱을 직접 써 보는 QA, 코드 리뷰(데이터 손실 관점), 업데이트 경로 E2E를 돌렸다.
- 찾은 문제는 고치고 다음 라운드에서 다시 확인했다.
- core 테스트 116개, 앱 자체 시험(`--selftest`, `--selftest-editor`), `design:check` BLOCK 0, `typecheck` 통과.
- 실제 라이브러리(`~/Library/Application Support/Ithaca`)는 시험에 쓰지 않았다. 모든 시험은 `ITHACA_LIBRARY_PATH`로 분리했다.

## 남은 일 (다음 후보)

- 한글 실제 입력 확인과 그에 따른 수정 (P0)
- 키 입력당 약 20ms 고정 비용. 잠긴 화면의 오프스크린 측정이라 실제보다 높을 수 있다. 실제 화면에서 다시 잰다.
- (확인됨) 메모리: 시트를 20번 오가도 약 100MB에서 늘지 않는다. 처음 보인 "시트당 400MB"는 성능 시험 루프의 측정 문제였다. `--selftest-mem`이 계속 감시한다
- Claude 쓰기 권한(고친 것을 actor=claude로 기록하고 되돌릴 수 있게), 본문 서체 · 줄 길이 설정, 동기화(iCloud/relay)
- iOS · Android · Windows는 여전히 디자인 동결 중이다(ADR-0006)
